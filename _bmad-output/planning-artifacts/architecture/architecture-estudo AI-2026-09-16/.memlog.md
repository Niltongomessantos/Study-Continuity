- (decision) Adopt a lean hexagonal modular monolith for the local MVP: domain rules are isolated from UI and infrastructure; ports are limited to persistence, clock, and local file access. This prevents independently built screens and storage adapters from owning conflicting Session lifecycle rules.
- (decision) Use a browser-first runtime for the MVP with no local backend. Persist the local domain in browser storage; local materials are attached through explicit browser file selection or external links, never arbitrary automatic filesystem scanning. This keeps the single-user MVP operationally simple.
- (decision) Use TypeScript with React and Vite for the browser UI. React components stay in the UI adapter layer; domain rules and application use cases remain framework-independent. Vite is the local development/build starter, not a domain dependency.
- (version) Official Vite documentation currently exposes Vite 7 documentation and the npm create vite@latest starter. MDN documents IndexedDB as asynchronous transactional browser storage for structured data and files/blobs. React version remains unpinned pending a direct official version source.
- (decision) Use IndexedDB behind the persistence port for the MVP. Store structured Local Domain records and selected file blobs/references transactionally; keep IndexedDB-specific APIs out of domain and application layers. This preserves a future adapter swap without adding SQLite/WASM complexity now.
- (decision) Timer recovery uses persisted timestamps rather than an in-memory interval. Time continues to elapse while the browser is closed or suspended; reopening reconstructs state from actualStartAt, plannedDuration, plannedEndAt, and current time. The domain remains responsible for the transition when the configured boundary is reached.
- (decision) A late-started Session keeps plannedEndAt = plannedStartAt + plannedDuration. The system records actualStartAt and shows lateness, but never extends the planned end automatically. This preserves the product rule that late arrival does not compensate lost scheduled time.
- (decision) Set the global Managed Lesson tolerance window to 50% of planned duration. A Session may start only while currentTime is before or at plannedStartAt + (plannedDuration * 0.5); after that boundary the domain marks it Lost, blocks Start, preserves it in history, and promotes the next valid Session and its start time on Home. PlannedEndAt remains plannedStartAt + plannedDuration, so a late start never extends the end. Compute fractional durations precisely rather than rounding to whole minutes.
- (decision) Apply the 50% tolerance window to both Managed Lessons and Free Blocks. The Local Domain governs whether either Session may start; external content control is irrelevant to local timing. After the boundary, either Session is Lost, Start is blocked, history is updated, and Home promotes the next valid Session.
- (decision) Use hybrid material persistence: external links store URL and metadata; selected small local files may store blob plus metadata in IndexedDB; large files store metadata and a re-selection reference rather than forcing browser storage. Material access failure never changes Session lifecycle state.
- (decision) Use versioned JSON for MVP backup and restore. Export includes schemaVersion, stable IDs, timestamps, Local Domain records, recurrence, replacements, material metadata, and eligible small-file blobs. Import validates the full document before replacing local state; large-file references remain reselectable.
- (decision) All Session mutations go through explicit application use cases; UI, timer display, and import cannot mutate entities directly. The domain validates transitions, and persistence commits current state with lifecycle events atomically. History preserves original Sessions, replacements, losses, completions, and manual adjustments.
- (decision) Start and Stop are idempotent use-case operations. Start is valid only for Pending Sessions within tolerance and never overwrites actualStartAt; repeated Start returns current state. Stop is valid only for Started Sessions; repeated Stop after a terminal state returns current state without a second lifecycle event. The domain emits at most one valid transition per operation.
- (decision) Use an injected domain Clock. The browser adapter supplies current time; UI intervals only refresh display. On open, focus, and every mutating action, reconcile Pending and Started Sessions from persisted timestamps. The domain marks overdue Pending Sessions Lost and resolves Started Sessions at plannedEndAt without depending on setInterval.
- (decision) Run the browser-first MVP through a local development/build server rather than file:// opening. Initialize versioned IndexedDB before rendering persisted data. Export versioned JSON and validate complete imports before replacement. Validate http/https links, accept local files only through explicit user selection, store file content as data, enforce size limits, and never let material-open failures mutate Session status.
- (decision) Timer UI shows both elapsed and remaining time. Store selected local file blobs up to a 5 MB per-file MVP limit; larger files retain metadata and require reselection. MVP assumes one active browser tab; cross-tab synchronization is deferred. JSON import validates schemaVersion, duplicate IDs, references, and cycles, then atomically replaces all local state. TypeScript and React versions remain unpinned until the starter is created.
- (event) spine finalized after reviewer gate; reconciliation, atomic persistence, import validation, material limits, timer display, single-tab scope, and entity seed clarified
